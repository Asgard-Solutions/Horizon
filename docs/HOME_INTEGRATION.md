## Implemented flow

Home opens with Movies and TV Shows, the supplied REELHEIM raven logo, Aurora Over the Midnight Fjord background, category artwork and gold media icons. The approved full gold selection glow and neutral mouse restoration are the locked visual baseline. Choosing a type opens `/home/movie` or `/home/tv`, with Atlas, Discover and Search as the three main choices. Continue Watching appears below only when the actual selected-type API returns valid unfinished movies or playable episodes. There is no initial hero, Filmstrip, Recently Added, recommendation feed or generated library content.

Settings is the only shared header utility. Library sources are managed under Settings → Libraries & scanning using the existing host LibraryManager. The former Sources page is removed; `/sources` redirects to the same Settings section while preserving the media filter. Paired devices retain the existing host-only management restriction. Existing scanning, SQLite schema, file authorization, streaming and player services remain in place. The old Stage/Filmstrip components are retained as existing browsing components but are not mounted on Home.

Destinations and detail/playback links carry `media=movie|tv`. The API accepts optional `media_type=movie|tv` on Home, Discover, Search and Atlas, applying it before pagination, limits, facets, groups and counts. Unscoped callers remain compatible. Scoped Home counts refer to that scope; the initial Home obtains global counts through the unscoped request. The current application has no user profiles, so no profile UI or fictitious profile filtering was added.

Continue Watching uses the existing unique progress-by-path record and completion flag. Scoped rows require finite duration and position, with `0 < position < duration`, and exclude watched records. Ordering is actual progress update time descending with file-ID tie-breaker. Offline entries stay indexed. The UI rechecks the existing stream service with HEAD before offering Resume/Start Over; playback metadata alone is not treated as evidence that a file is reachable. No progress is cleared by Home or opening a dialog.

## Local subtitles — November 4, 2026

Playback settings now replace the Local subtitle files placeholder with Off by default / Automatic. Existing saved preferences remain compatible and default to Off. Automatic prefers a matching browser language, then an untagged track, then the first deterministic track. The Subtitles player dialog always allows manual selection or Off, with loading, empty and retry states. A missing or invalid subtitle does not stop the video or erase progress. Each video/episode has its own selection; the next episode cannot inherit the preceding episode's sidecar.

Discovery reads only matching `.srt`/`.vtt` siblings of an indexed movie or episode: exact video basename or dot-separated language/variant suffixes, including common three-letter language codes. No rescan is needed. Separate viewer-authenticated `GET /api/files/{id}/subtitles` and `GET /api/files/{id}/subtitles/{track_id}` endpoints prevent subtitle errors blocking playback metadata. Opaque filename hashes are resolved through the current matching list; media/library/sidecar confinement is revalidated on every read. Links and out-of-folder paths are rejected. Conversion is in memory, leaving original files read-only; responses use UTF-8 `text/vtt` and `Cache-Control: no-store`.

Supported encodings: UTF-8 with/without BOM, BOM-marked UTF-16 and Windows-1252 fallback. Conversion retains line breaks and basic bold/italic/underline, discarding other markup, VTT STYLE/REGION/NOTE blocks, identifiers and positioning. Limits: 2 MiB per track, 10,000 cues, 64 matching tracks and 10,000 folder entries. Embedded-track extraction, ASS/SSA, image subtitles, recursive subtitle folders, downloading and transcoding remain unavailable. Other legacy encodings need conversion to UTF-8. Folder reachability is checked, but a subsequent stalled filesystem read has no hard timeout.

Native browser text tracks render subtitles. Native load/error listeners and cached ready-state checks correct the initially reproduced React track-load event issue; stale listeners are removed and a 15-second timeout reports stalled loading. Cues move above the custom controls and lower with extra margin when controls hide. The dialog traps Tab, B/Escape restores its opener, retry keeps a stable focusable control, and playback ending preserves dialog focus; autoplay countdown starts after the dialog closes.
